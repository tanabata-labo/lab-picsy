# はじめに

[1回目](./01-spec-and-lean.md) で伝播投資貨幣 PICSY を仕様に落として Lean で証明し、[2回目](./02-link-farm.md) で少人数の共謀に弱いことを示して、予算の下限 $\varepsilon$ という直し方を提案しました。最終回は、PICSY を実際に社会で動かすときのハードルを3つの層に分けて考えます。

1. **計算**: 参加者が増えたとき、1回の支払いにどれだけ計算が要るか
2. **法と制度**: 日本円との交換を保証しない前提で、何が論点になるか
3. **仕様と社会の境目**: 紛争が起きたときに取引を取り消せるか

想定しているのは、国家の通貨ではなく、オンラインのコミュニティの中で依頼や評価に使う規模（数百〜1万人程度）です。

# 計算: 1万人でも1回の支払いは数ミリ秒

## 素直に解くと、1万人で30秒

貢献度 $c$ は $c E' = c$ 、 $\sum c_i = N$ を満たすベクトルです。1回目の仕様（決定 D3）では、これを $N \times N$ の連立一次方程式として直接解きます。そのため計算量は $O(N^3)$ 、メモリは $O(N^2)$ になります。手元の12スレッドの Windows 機で測った結果が次の表です。

| $N$ | 密な直接法 | メモリ |
|---|---|---|
| 100 | 2〜22 ms | 0.2 MB |
| 1000 | 約0.4 s | 16 MB |
| 3000 | 0.5〜0.9 s | 144 MB |
| 10000 | 約30 s（ $N^3$ で外挿） | 1.6 GB |

研究に使う分には足りますが、支払いのたびに解き直す方式には向きません。

## 構造を使うと、1万人で数ミリ秒

$E'$ は、「誰が誰を評価したか」を表す部分と、「予算を全員へ均等に配る」部分の和に分けられます。

```math
E' = E_{\mathrm{off}} + \frac{\mathrm{diag}(b)(\mathbf{1}\mathbf{1}^\top - I)}{N-1}
```

$E_{\mathrm{off}}$ は対角を除いた評価、 $b$ は予算のベクトルです。1人が実際に評価する相手は限られるので、 $E_{\mathrm{off}}$ は疎行列です。均等配分の部分は行列を作らなくても、ベクトルの演算だけで計算できます。

```math
c E' = c E_{\mathrm{off}} + \frac{(c \cdot b) \mathbf{1}^\top - c \circ b}{N-1}
```

この積を繰り返すべき乗法なら、1回の反復の計算量は「評価の数＋ $N$ 」に比例します。さらに、1回の支払いで変わるのは $E$ の2成分だけなので、支払い直前の $c$ から反復を始めればすぐに収束します。1人あたりの評価相手を50人として測った結果が次の表です。

| $N$ | 反復法の時間/支払い | 反復回数 | メモリ |
|---|---|---|---|
| 100 | 0.2 ms | 8〜10 | 0.1 MB |
| 1000 | 0.5 ms | 7〜8 | 1.2 MB |
| 3000 | 1 ms | 6〜8 | 3.6 MB |
| 10000 | **3〜4 ms** | 6〜7 | **12 MB** |

密な直接法との差は最大 $1.7 \times 10^{-10}$ でした。

ただし、評価の相手をランダムに選ぶと網全体がよく混ざるので、反復が速いのは当然です。そこで最悪に近い場合として、10人ずつの閉じた小集団に分かれ、集団の外へは予算の配分しか流れない網でも測りました。 $N = 10000$ 、 $\varepsilon = 0.02$ で、直前の $c$ から始めて26回・4.4 ms、一様な初期値からでも90回・9.5 ms でした。

## 予算の下限は収束の速さも保証します

1回目の D3 でべき乗法を避けたのは、収束の速さに保証が無いからでした。2回目で提案した予算の下限 $\varepsilon$ を入れると、全員の行から $\varepsilon/(N-1)$ 以上が全員へ流れます。その結果、誤差は反復1回ごとにおおよそ $(1-\varepsilon)$ 倍以下に縮みます。下限が無いと、予算を使い切った閉じた輪がある状態（2回目の P7）では、反復は収束しません。

つまり予算の下限を入れると、共謀への耐性（P8）、貢献度の一意性（P2）、計算の速さの3つが同時に成り立ちます。

## サーバでの動かし方

サーバ1台のメモリに疎行列と予算のベクトルを載せておくだけで十分です。 $N = 10000$ でも、1秒に数百件の支払いを処理できます。自然回収は全員の行を同時に変えますが、 $E_{\mathrm{off}} \leftarrow (1-\gamma)E_{\mathrm{off}}$ 、 $b \leftarrow (1-\gamma)b + \gamma\mathbf{1}$ と書けるので、これも軽い計算です。

ただし、仕様に1つ足す必要がある点が見つかりました。評価は自然回収で $(1-\gamma)$ 倍ずつ減るだけで、0にはなりません。放っておくと $E_{\mathrm{off}}$ が密になっていくので、一定より小さくなった評価は予算へ戻して疎に保つ規則が要ります。予算へ戻すだけなので、非負性と行和1は保てます。

# 法と制度: 日本円と交換しない場合でも残る論点

ここからは法律の話です。以下は技術側からの論点の整理で、法律の専門家の判断ではありません。条文の最新の文言も確かめていないので、実際に動かす前には弁護士・税理士への確認が必要です。

## 金融規制は避けやすい作り

日本円との交換を保証しない前提に立つと、金融の規制はかなり避けやすくなります。

- 前払式支払手段（資金決済法）は、対価を得て発行するものが対象です。円で買えない PICSY は当たりにくいと考えられます
- 暗号資産（同法）は、不特定の者を相手に円などと売買できる財産的価値であることが要件です。換金しない前提なら外れる方向です
- そもそも PICSY は、トークンを手渡す仕組みではありません。評価行列から購買力を計算する仕組みなので、「移転できる財産的価値」に当たるかどうかも疑わしいところです

ただし、気をつける点が2つあります。1つは利用者どうしの換金です。「円を払うから PICSY で依頼してくれ」という取引が広がれば、PICSY は実態として円と交換できる価値になります。そのため、利用規約で禁止し、運営が見張る設計が要ります。もう1つは、加入時に払うお金と購買力を結びつけることです。たとえば加入料の見返りに初期の予算を与えると、対価を得て発行するものに近づきます。論文どおりなら、PICSY の新メンバーは予算0で加わり、自然回収で予算が増えていきます。この形を崩さないことが安全です。

## 大きな論点は労働・税・個人情報

| 論点 | 中身 |
|---|---|
| 賃金の通貨払い（労働基準法24条） | 雇用している人の仕事の対価を PICSY で払うことはできない。組織の中で使うなら、あくまで評価にとどめ、給与と切り離す |
| フリーランスとの取引（2024年11月施行のフリーランス・事業者間取引適正化等法） | 外部の個人に業務を委託するなら、報酬額の明示と期日内の支払いが要る。PICSY だけを報酬にすることはできない |
| 税 | 金銭以外の経済的な利益も、原則として所得になる。PICSY で実際のサービスを受け取ると課税の対象になりうるので、評価額の算定方法が問題になる |
| 個人情報 | 評価行列は「誰が誰をどれだけ評価したか」そのもので、貢献度は人の格付けとして機能する。利用目的の明示、公開する範囲の設計、本人による閲覧・訂正への対応が要る |

オンラインのコミュニティで依頼や評価に使う程度なら、PICSY は「通貨」というより「評判の仕組み」に近い位置づけになります。その場合に主に問題になるのは、個人情報と、雇用している人の評価と賃金を切り離すことの2点です。

## 制度として決めること

まず、本人確認は前提条件です。論文自身も5.1節で、偽の登録には強い誘因があり PICSY だけでは防げないと書いています。PICSY では、新メンバーの登録だけが新しい貢献度を生むからです。さらに、PICSY の貢献度のように全員に共通の評判の関数は、なりすましの複数登録（Sybil）に完全には耐えられないことが知られています（Cheng & Friedman 2005）。そのため、戸籍名と結びつけるかはともかく、決済手段（クレジットカードなど）と紐付けて、1人が複数の口座を持つコストを上げる必要があります。ただし、前節のとおり、カードで払うお金と購買力は結びつけません。

次に、パラメータを決める主体が要ります。回収率 $\gamma$ や予算の下限 $\varepsilon$ を変えると、全員の購買力が一斉に動きます。この点で、パラメータの変更は金融政策とほぼ同じです。

| PICSY | 中央銀行の道具 |
|---|---|
| 自然回収の回収率 $\gamma$ | 通貨の減価。評価の寿命を決める、いちばん影響の大きいパラメータ |
| 予算の下限 $\varepsilon$ | 準備預金の比率に近い。使い切れない部分を、社会全体への流れとして強制する |
| 加入と本人確認 | 通貨を発行する範囲（誰がこの経済の参加者か） |
| 取引の取り消し | 決済の取り消しと紛争処理 |

論文の方式の名前が「仮想中央銀行法」なのは偶然ですが、パラメータを決めるチームには、実在の中央銀行に求められるものがそのまま当てはまります。具体的には、運営の都合で動かさない独立性、変更を事前に告知し自然回収の区切りでだけ行うといったルールに基づく運用、変更の理由を公開する透明性です。

最後に、アルゴリズムは公開します。貢献度の計算は人の格付けとして働くので、計算方法が見えないと、参加者は自分の貢献度が正しく計算されているかを確かめられません。この連載の仕様書・参照実装・Lean の証明は、そのまま公開できる形にしてあります。

# 仕様と社会の境目: 取引の取り消し

紛争の解決（誰が、どの取引を、なぜ取り消すか）は、人が判断する社会の層の仕事です。ただ、取り消したときに状態がどう変わるかは、仕様の側で決めて保証しておく必要があります。ところが、論文には取り消しの定義がありません。

## 単純に逆の取引をしても元に戻りません

取引のあとに自然回収が挟まると、取引で付けた評価 $\alpha$ はすでに $(1-\gamma)$ 倍に減っています。そのため、逆向きの取引で $\alpha$ をそのまま差し引くと引きすぎになります。

## 残量を差し引けば正確に戻ります

取引は $E$ に一定の行列を足す操作で、自然回収は $E \mapsto (1-\gamma)E + \gamma I$ というアフィンな操作です。そのため、ある取引が後の状態に残す影響は、あいだに他の取引がいくつ挟まっていても、その後の自然回収の $(1-\gamma)$ を掛け合わせた量

```math
r = \alpha \prod_{t=1}^{k} (1 - \gamma_t)
```

だけになります。取り消しは、この $r$ を逆向きの取引として差し引く操作と決めました（決定 D13）。Lean では、取引と自然回収の列を型 `Op` で表し、列の長さについての帰納法で次を示しました。

```lean
/-- 取引 (b, s, α) のあとに操作列 ops が続いた状態から、残量 decay ops α を逆向きに
    差し引くと、その取引をしなかった場合の状態に正確に一致する。 -/
theorem cancel_exact (ops : List (Op n)) (E : Mat n) (b s : n) (α : ℚ) :
    transact (applyOps (transact E b s α) ops) b s (-(decay ops α)) = applyOps E ops
```

取り消した後の状態が非負性と行和1を保つこと（`cancel_stochastic`）も証明しました。取り消しは買い手の予算を増やすだけなので、実際の列で前提を満たしていた取引は、取り消した世界でも前提を満たします。

## 戻らないもの

仕様が保証するのは、状態 $E$ が戻ることだけです。次のものは戻らず、社会の層で扱います。

- 二次的な影響: 取り消した取引で上がった貢献度を使って、売り手が安く買えた分など
- 加入を挟んだ場合: 新メンバーの行は、取り消す取引を含んだ貢献度から作られているので、正確には戻らない
- 時間による弱まり: 時間が経つほど $r$ は小さくなり、取り消しの効果も薄れる。取り消しを受け付ける期限は運用で決める

「何がどう戻るか」は仕組みが保証し、「誰が、どの取引を、なぜ取り消すか」は人が決めます。この分け方が、仕様と社会の境目です。

# 連載のまとめ

3回で、伝播投資貨幣 PICSY の仮想中央銀行法について次のことを示しました。

- 論文を仕様に落とすために、13の決定（D1〜D13。予算の下限の D12 はまだ提案の段階）を置いた
- 不変条件、加入、離脱、一意性、共謀への耐性、取り消しなど9つの性質（P1〜P9）を Lean で証明した
- 論文5.1節の「予算の制約があるので link farm は難しい」は成り立たない。予算を使い切った組は吸収集合になる
- 取引で予算を下限 $\varepsilon$ 未満にできないルールを入れると、共謀の取り分に上限が付き、貢献度の一意性と計算の速さも保証される。論文の貢献度の定義は変えない
- 1万人規模でも、1回の支払いの計算は数ミリ秒で済む
- 残るハードルは計算ではなく、本人確認・パラメータの決め方・紛争の解決・労働と税と個人情報の扱いといった、社会の層にある

PICSY が「機能し、破綻しないこと」は、少なくともこの範囲までは示せたと考えています。
